# დანართი A — სათადარიგო ნაწილების ნავიგაცია და თავსებადობა

Nov 7, 2026 · @George

## 1. სტატუსი და მთავარი პრინციპი

მე-8 კატეგორიის საჯარო ნავიგაცია აიგება იმის მიხედვით, თუ **რომელ ტექნიკას ერგება** ნაწილი, და არა მხოლოდ იმის მიხედვით, თუ **რა არის** ის. ეს დანართი ავსებს დოკუმენტს „კატეგორიების არქიტექტურა v1.0“ (§11, §12, §15) და მასთან ერთად განიხილება.

სტატუსი: რეკომენდაცია. ის არ ცვლის 8 მთავარ კატეგორიას და 30 Product Type-ს; მხოლოდ ამატებს მონაცემთა მოდელის ელემენტებს და საჯარო ნავიგაციის წესებს.

ნაწილს ორი დამოუკიდებელი ღერძი აქვს:

| ღერძი | კითხვა | მნიშვნელობები |
| --- | --- | --- |
| A — იდენტობა | რა არის? | Product Type (ENGINE / SPARE\_PART / ACCESSORY / CONSUMABLE) + subtype |
| B — თავსებადობა | რას ერგება? | host-ტექნიკის ტიპი → ბრენდი → Family/მოდელი, ან ძრავის მოდელი |

primary\_category ყოველთვის 08 რჩება. ერთი SKU-ის გამოჩენა რამდენიმე host-კვანძში მენიუს ხედია და არა დუბლირება.

## 2. მონაცემთა მოდელის დამატებები

საჭიროა სამი ახალი ელემენტი; არსებული `skus` და `product_types` სტრუქტურა არ იცვლება.

**part\_subtypes** — კონტროლირებადი ლექსიკონი, არა თავისუფალი ტექსტი. თითო subtype-ს აქვს სავალდებულო spec-ველები:

| subtype (მაგალითი) | Product Type | სავალდებულო spec-ველები |
| --- | --- | --- |
| CHAIN | SPARE\_PART | ნაბიჯი, სისქე (მმ), რგოლების რაოდენობა |
| GUIDE\_BAR | SPARE\_PART | სიგრძე (სმ/დიუმი), ნაბიჯი, სისქე |
| AIR\_FILTER | SPARE\_PART | ზომები, ძრავის მოდელი |
| SPARK\_PLUG | SPARE\_PART | კოდი, ხრახნის ზომა |
| BELT | SPARE\_PART | პროფილი, სიგრძე |
| TILLER\_TINE | SPARE\_PART | მხარე (მარცხ./მარჯვ.), ლილვის დიამეტრი |
| TRIMMER\_LINE | CONSUMABLE | დიამეტრი (მმ), პროფილი, სიგრძე (მ) |
| WELDING\_ELECTRODE | CONSUMABLE | დიამეტრი (მმ), მარკა |

**compatibility** — ნაწილისა და სამიზნის კავშირი:

| ველი | მნიშვნელობა |
| --- | --- |
| part\_sku\_id | ნაწილის SKU |
| target\_level | PRODUCT\_TYPE / BRAND / FAMILY / SKU / ENGINE\_MODEL |
| target\_id | კონკრეტული სამიზნე |
| fit\_status | CONFIRMED / LIKELY / UNVERIFIED |
| evidence | part number, შეფუთვა, მწარმოებლის დოკუმენტი, ფიზიკური მორგება |
| note | მაგ. „საჭიროებს ადაპტერს“ |

**uses\_engine** — ტექნიკის Family-ის ან SKU-ის კავშირი ძრავის მოდელთან (170F, 178F, 186F...), საკუთარი fit\_status-ითა და evidence-ით. ძრავის მოდელი ცალკე ცნობარია (`engine_models`) და არ ემთხვევა ENGINE SKU-ს: ერთ ძრავის მოდელს შეიძლება ჰქონდეს რამდენიმე გასაყიდი ENGINE SKU ან არც ერთი.

## 3. ძრავის მოდელი, როგორც თავსებადობის ცენტრი

ძრავის კოდი ბრენდზე სტაბილური იდენტიფიკატორია. ბევრი მოტობლოკი, ტუმბო და გენერატორი სხვადასხვა ბრენდით იყიდება, მაგრამ შიგნით სტანდარტული 170F / 178F / 186F ტიპის ძრავი უზის.

&#91;embedded content: თავსებადობის მემკვიდრეობა ძრავის მოდელის გავლით\]

მემკვიდრეობის წესი: ნაწილი ტექნიკის გვერდზე ჩანს მაშინ, როცა ორივე რგოლი — ნაწილი → ძრავის მოდელი და ტექნიკა → ძრავის მოდელი — CONFIRMED-ია. თუ რომელიმე რგოლი LIKELY-ა, შედეგიც LIKELY-ა და საჯაროდ არ ჩანს. ერთი კავშირი ათობით მოდელს ფარავს ხელით მიბმის გარეშე.

## 4. Spec-ზე დაფუძნებული შესაბამისობა

ზოგი ნაწილი ერგება არა მოდელს, არამედ ზომას: ჯაჭვი, შინა, ძუა, სანთელი, ღვედი. მათთვის მოდელების ხელით ჩამოთვლა არარეალურია, ამიტომ სისტემა spec-ველებს ადარებს.

მაგალითი: ჯაჭვი 3/8" / 1.3 მმ / 52 რგოლი ემთხვევა ხერხს, რომლის შინის ჩანაწერშიც იგივე სამი მნიშვნელობაა.

საჯაროდ ორი სტატუსი სხვადასხვა ფორმულირებით ჩანს:

| ტიპი | საჯარო ტექსტი | რას ნიშნავს |
| --- | --- | --- |
| დადასტურებული კავშირი | „ერგება: Husqvarna 137“ | CONFIRMED ჩანაწერი compatibility-ში |
| spec-დამთხვევა | „შეესაბამება ზომით: 3/8", 1.3 მმ, 52 რგოლი“ | მყიდველს ეუბნება, რა შეამოწმოს; კონკრეტულ მოდელზე პირობას არ დებს |

spec-დამთხვევა ავტომატურად არასოდეს იქცევა CONFIRMED-ად. ის მხოლოდ შედარებაა იმ ველებისა, რომლებიც ორივე მხარეს დადასტურებულია; თუ რომელიმე მხარეს ველი NOT\_FOUND-ია, დამთხვევა არ გამოჩნდება.

## 5. საჯარო ნავიგაცია

მე-2 დონის კვანძები ავტომატურად იწარმოება compatibility-დან და მენიუში ჩნდება მხოლოდ ზღვრის გადაჭარბებისას (საწყისი შეთავაზება: ≥4 გამოქვეყნებული SKU). ქვემოთ მოცემული 10 კვანძი სრული სიაა; გაშვებისას მათი ნაწილი სავარაუდოდ დამალული იქნება.

&#91;embedded content: მე-8 კატეგორიის საჯარო ნავიგაცია · 3 დონე\]

- ზღვრის ქვემოთ კვანძი „სხვა ნაწილებში“ არ ერთიანდება. ნაწილი ხელმისაწვდომია ტექნიკის გვერდიდან, ძიებით და 08-ის ფილტრით „რომელი ტექნიკისთვის“.
- „უნივერსალური ნაწილების“ საჯარო კვანძი არ იქმნება; ასეთი ნაწილები subtype-ითა და spec-ფილტრებით მოიძებნება.
- ერთი SKU შეიძლება რამდენიმე კვანძში ჩანდეს: 178F-ის ფილტრი ჩანს „ძრავის ნაწილებში“ და „მოტობლოკისა და კულტივატორის ნაწილებში“.
- spec-ფილტრები ჩნდება მხოლოდ ერთი subtype-ის არჩევის შემდეგ; საერთო გვერდზე მხოლოდ ტიპი, ბრენდი და მოდელი ჩანს.
- კვანძების სახელები და წყობა storefront-ის ნავიგაციის ფენაშია: მეორე მაღაზიას შეუძლია სხვაგვარად დაალაგოს ისინი compatibility-ს შეცვლის გარეშე.

## 6. „იპოვე ნაწილი შენი ტექნიკისთვის“

selector-ს ორი შესასვლელი აქვს, რადგან ბევრმა მყიდველმა ბრენდი არ იცის ან ტექნიკა სხვა სახელით იყიდა, მაგრამ ძრავზე კოდი ამოტვიფრულია.

1. **ტექნიკით:** ტიპი → ბრენდი → მოდელი.
2. **ძრავის კოდით:** „ვიცი ძრავის კოდი“ → 170F / 178F / 186F...

selector ჩანს 08-ის მთავარ გვერდზე და თითოეული ტექნიკის გვერდზე. შედეგი არის host-კვანძის ფილტრირებული ხედი, არა ცალკე გვერდი.

Intake-ის ფოტოინსტრუქციაში ძრავის ფირფიტის ფოტო ყველა ძრავიან ტექნიკაზე სავალდებულოა: სწორედ ის ავსებს uses\_engine-ს.

## 7. ორმხრივი ბმები გვერდებზე

**ტექნიკის გვერდზე** — ბლოკი „ნაწილები და აქსესუარები ამ მოდელისთვის“, დაჯგუფებული subtype-ით:

- ჯერ CONFIRMED კავშირები (პირდაპირი ან ძრავის გავლით);
- შემდეგ, ცალკე სათაურით, „ზომით შესაბამისი“ (spec-დამთხვევა);
- LIKELY და UNVERIFIED საჯაროდ არ ჩანს.

**ნაწილის გვერდზე** — „ერგება:“ მოდელების სიით და ძრავის კოდით. თუ CONFIRMED კავშირი ჯერ არ არის, ცარიელი ადგილის ნაცვლად ჩანს CTA: „არ ხართ დარწმუნებული, ერგება თუ არა? გამოგვიგზავნეთ ტექნიკის ფირფიტის ფოტო“.

CTA-ით მიღებული ფოტო Hub-ში review-ის ჩანაწერად ბრუნდება. დადასტურების შემთხვევაში ის ახალ CONFIRMED კავშირად ინახება, evidence-ად კი კლიენტის ფოტო ერთვის.

## 8. SPARE\_PART / ACCESSORY / CONSUMABLE

არქიტექტურა v1.0-ში ჯაჭვი ორ ტიპს შორის „რეალური როლის მიხედვით“ ნაწილდება. ერთი ტესტი ამ გაურკვევლობას ხსნის:

| ტიპი | ტესტი | მაგალითები |
| --- | --- | --- |
| SPARE\_PART | ცვლის ტექნიკის არსებულ, ცვეთად ან გატეხვად კომპონენტს; ფუნქციას აღადგენს | ჯაჭვი, შინა, კარბურატორი, ფილტრი, ღვედი, ფრეზის დანა |
| ACCESSORY | ამატებს ან აფართოებს ფუნქციას; სამუშაოს თან ახლავს, მაგრამ არ იხარჯება | ნიღაბი, ხელთათმანი (PPE), ადაპტერი, დამატებითი საჭრელი თავაკი, ბურღის პირი |
| CONSUMABLE (ახალი) | იხარჯება ექსპლუატაციისას და რეგულარულად მეორდება | ზეთი, ძუა, აბრაზიული დისკი, მავთულის ჯაგრისი, ელექტროდი, ცხიმი |

CONSUMABLE ცალკე ტიპად გირჩევთ, რადგან ეს ნივთები ხშირად მეორდება შეკვეთებში და ცალკე ტიპად განმეორებითი გაყიდვების საფუძველია; ACCESSORY-ში ისინი დაიკარგება. დამატება არქიტექტურის წესს შეესაბამება: განსხვავებული ბუნება და განსხვავებული ფილტრები.

შესწორება (07.11.2026): აბრაზიული დისკი თავდაპირველად შეცდომით ეწერა ACCESSORY-ის მაგალითად; ტესტის მიხედვით ის CONSUMABLE-ია. სამივე ტიპის სრული სპეციფიკაცია: დანართი B — ახალი Product Type-ები.

## 9. Intake, review და ორსაფეხურიანი გამოქვეყნება

ნაწილი არ იბლოკება მხოლოდ იმიტომ, რომ თავსებადობა ჯერ დაუდასტურებელია, მაგრამ საჯაროდ არც ის ცხადდება, რაც არ ვიცით.

| ეტაპი | მოთხოვნა |
| --- | --- |
| მიღება | subtype სავალდებულოა; ფოტო part number-ით ან შეფუთვით |
| კვლევა | AI თავსებადობას part number-იდან და შეფუთვიდან სთავაზობს, მხოლოდ LIKELY სტატუსით |
| დადასტურება | ადმინი LIKELY-ს CONFIRMED-ად აქცევს evidence-ის მითითებით |
| გამოქვეყნება — დონე 1 | subtype + spec-ველები შევსებულია → ნაწილი ჩანს 08-ში subtype-ფილტრით და ძიებაში |
| გამოქვეყნება — დონე 2 | ≥1 CONFIRMED კავშირი → ნაწილი ჩანს host-კვანძში და ტექნიკის გვერდზე |

თუ subtype ვერ დადგინდა, ნაწილი რჩება UNCLASSIFIED / IDENTIFICATION\_REQUIRED სტატუსში და საჯაროდ არ ქვეყნდება.

## 10. სრული მაგალითი: ჰაერის ფილტრი 178F

ერთი დადასტურებული კავშირი ნაწილს ოთხ საჯარო ადგილას აჩენს, ისე რომ არცერთი ხელით მიბმა არ სჭირდება.

1. Intake: შეფუთვაზე წერია „178F“ და part number.
2. იდენტობა: SPARE\_PART, subtype AIR\_FILTER, spec-ველები — ზომები.
3. compatibility: ENGINE\_MODEL = 178F, CONFIRMED (evidence: შეფუთვა + ფიზიკური მორგება).
4. HIROMIKI 178FE მოტობლოკს აქვს uses\_engine = 178F, CONFIRMED (evidence: ფირფიტის ფოტო).
5. შედეგი — ფილტრი ავტომატურად ჩანს:
   - „ძრავის ნაწილებში“;
   - „მოტობლოკისა და კულტივატორის ნაწილებში“;
   - HIROMIKI 178FE-ს გვერდზე;
   - ნებისმიერი ტუმბოს ან გენერატორის გვერდზე, რომელსაც დადასტურებულად 178F უზის.

თუ მე-4 ნაბიჯი LIKELY იქნებოდა, ფილტრი ტექნიკის გვერდზე არ გამოჩნდებოდა, თუმცა „ძრავის ნაწილებში“ დარჩებოდა.
